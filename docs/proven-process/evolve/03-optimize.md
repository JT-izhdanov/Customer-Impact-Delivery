## Customer Impact integration points

Optimize is the recurring-revenue engine (support contracts) — the plan connects its case-level machinery to account-level impact:

- **The 20-hour rule is a built-in expansion sensor — instrument it.** Cases above ~20 hours already route to account managers as leads. For impact accounts, that routing should carry outcome context: which metric the request serves, so the lead enters Envision outcome-labeled (the flywheel from the Evolve exit gate). Track how many of these convert — it's a free leading indicator for "New Non-Support Projects."
- **Severity triage already speaks impact language.** Severity is assigned "based on business priority & end user impact" — for impact accounts, the sharpest tiebreaker is whether the case touches a hypothesis metric (an integration failure in the order-to-cash flow is not the same severity as a cosmetic bug, even if both annoy one user equally).
- **Case patterns feed the SBR's first 15 minutes.** Recurring case themes (workarounds, repeated user errors, abandonment signals) are adoption early-warnings. A quarterly one-paragraph case-pattern summary per impact account, prepared by support for the SBR/VRR, closes the sensor loop at near-zero cost.
- **Support contract renewal is an impact conversation.** "Support Contracts Active and Current" is Evolve's recurring-revenue base; renewal conversations for impact accounts open with the Impact Scorecard, not the ticket count — "here's what the system earned you this year" renews contracts that "we closed 47 cases" cannot. This is also where the plan's managed-impact retainer (doc 06) attaches most naturally.
- **"Adoption is strong and growing" gets the same telemetry as everywhere else.** One adoption dashboard serves Stabilize, Validate, Manage, and Optimize — built once (Data & AI, per doc 06 measurement infrastructure), read by four sub-stages.
