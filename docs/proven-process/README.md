## Why this is documented in the Customer Impact repo

1. **It's a constant.** The board flagged that a visible not-changing list is part of the strategy (session 01, Rumelt). The Proven Process anchors that list.
2. **Customer Impact must land inside it.** Every Customer Impact artifact (Impact Hypothesis, Value Baseline, VRR) is mapped to a Proven Process stage and sub-stage — see the "Customer Impact integration points" section in each stage doc.
3. **The reconciliation is the design work.** Where the plan and the Proven Process pull in different directions (e.g., stage metrics vs. outcome metrics), the tension is named in the stage doc and routed to the backlog — not papered over.
